# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

A configurable DIY project repository for building Halo MJOLNIR cosplay suits. It combines German documentation, Python generators (`tools/`), parametric OpenSCAD concept CAD (`Design/`), embedded code (`Code/`) and a static web app (`web/`, deployed to GitHub Pages). No physical build evidence exists yet: all readiness gates are open.

The active workflow uses independent project profiles (32 measurements, fit
settings, armor reference, material, operating mode and optional equipment).
Start at Documentation/Guides/Mjolnir-Konfiguration.md. Template.json must stay
unmeasured; Demo.json is explicitly synthetic and never a default body. Profiles
and outputs use separate directories. Evidence belongs to a project and revision;
software checks never count as hardware approval. Selecting a material or
reference does not generate verified detail CAD or engineering calculations.

Three legacy material-reference variants exist: V1 Einsteiger (foam), V2 Fortgeschritten (3D-print/hybrid with HUD), V3 Profi (exoskeleton + premium).

## Code / Electronics

### HUD Display (Python, runs on Raspberry Pi Zero 2 W)
- `Code/HelmetControl/hud_display.py` - main HUD loop driving a transparent OLED (SSD1309) over I2C
- Dependencies: `pip install -r Code/HelmetControl/requirements.txt` (luma.oled, Pillow, smbus2)
- Config: copy `config.example.json` to `config.json`; battery status via `battery.example.json` to `battery.json`
- Hardware tests remain manual; fit/budget/readiness tests: `python3 -m unittest discover -s Tests/Automation -v`
- Web/exhibition unit tests: `node --test Tests/Automation/*.test.cjs`
- Firmware logic on the host: `python3 Tests/Firmware/run.py` compiles the two MultiEffects sketches unchanged against mock Arduino headers (g++) and tests `Code/ExoControl/LegAssist/exo_core.h` and `bench_core.h`; not a hardware test
- Stale-output checks: `python3 tools/suit_catalog.py --check`, `tools/suit_budget.py --check`, `tools/suit_readiness.py --check`, `tools/suit_loads.py --check` (rerun after editing `Design/Exo/Parameters.scad` or `LoadCase.json`), `tools/suit_sitemap.py --check` (regenerate `sitemap.xml` after adding or removing any `.md`)
- `Design/Parametric/Generated/` is committed output of `tools/suit_fit.py --profile Design/Parametric/Profiles/Demo.json --concept --out Design/Parametric/Generated`; a test compares it byte for byte
- Pages deploy (`.github/workflows/pages.yml`) runs the tests first and publishes tracked files only, without `.github/`, `docs/`, `Tests/Automation`, `Tests/Browser`, `CLAUDE.md`
- Readiness: a passed gate needs project name, profile binding and real evidence; generated files and the profile itself are rejected as evidence
- Runtime math: powerbank mAh refer to 3.7 V cells; always compute runtime from Wh (see `Elektronik-Strombudget.md`), never mAh / load current at 5 V
- All writers of `hud_state.json` must use `hud_state.merge()` (file lock + atomic replace) so modules don't clobber each other's keys

### Voice control + vision (Python, Raspberry Pi 5, optional)
- `Code/HelmetControl/voice_control.py` - push-to-talk voice commands (Vosk), I2C to helmet Arduino, optocoupler "button presses" to thruster/armor Arduinos, helmet radio voice (Audio Option C)
- `Code/HelmetControl/vision_bridge.py` - AI Camera (IMX500) detections -> `vision_contacts` in `hud_state.json` -> motion tracker
- Guide: `Documentation/Guides/Elektronik-Sprachsteuerung.md`

### Arduino Controllers
- `Code/Examples/HelmetControl/MainControlCode.ino` - basic I2C slave; accepts the same `[cmd, value]` protocol as HelmetMultiEffects but only applies brightness (0x01)
- `Code/HelmetControl/HelmetMultiEffects.ino` - **advanced**: 5 visor effects + I2C commands + fan PWM + button switching
- `Code/ArmorControl/MultiEffects.ino` - **advanced**: 5 LED effects + button switching + boot sequence + shield-hit touch sensors + handler alert
- `Code/Examples/` - four minimal test sketches (helmet/armor `MainControlCode.ino`, `LightingEffectsCode.ino`); builds use the MultiEffects controllers
- Compiled via Arduino IDE or `arduino-cli compile`; pin assignments must be adapted per build. CI compiles every sketch (AVR Nano, ESP32 SensorFeeder, ESP32-S3 Cortana chip); add new sketches to `.github/workflows/ci.yml`
- `Code/ExoControl/LegAssist/` - ESP32 + CAN controller for the self-built hip/knee drive X01; all control and safety logic lives in the hardware-free `exo_core.h`. Concept only: never describe it as built, tested on a person or safe; guide `Documentation/Guides/Exoskelett-Eigenbau.md`
- LED effect patterns documented in `Documentation/Guides/LED-Effekte.md`

## Conventions

- All documentation is in **German** (ASCII-safe: ae/oe/ue instead of umlauts)
- Markdown files use `#` heading hierarchy; no frontmatter
- File and folder names use PascalCase (e.g., `BuildGuides`, `ShoppingList.md`); `web/`, `tools/`, `docs/` are lowercase exceptions
- Python lint in CI: `ruff check --select E9,F tools Code Tests Design`
- The main page loads no third-party assets except the Sentry SDK; Tailwind is prebuilt (`web/vendor/README.md` has the rebuild command, needed after adding new utility classes), fonts live in `web/fonts/`
- No 0-byte placeholder files; CI enforces ASCII in `.md`, `.ino`, `.py` and checks relative links
- Contributions follow fork-and-PR workflow (see CONTRIBUTING.md)
